  Usage: /build-module 7 works. So do 07, m07 and 0 (the scaffold). It's

  What it does when called:
  1. Finds the module. It maps the number to its folder in docs/plans/ (for
     example 7 → m07-dedupe). It reads that folder's plan.md, tests.md and
     tasks.md, plus the technical spec and the plans README. A bad or missing
     number stops it and lists the valid folders.
  2. Checks dependencies. It uses the "Depends on" column in the README, so it
     knows m06 comes before m05. If a dependency's tasks aren't all ticked, it
     stops and tells you which module to build first. If the module is already
     fully ticked, it says so and stops. If it's partly done, it resumes from
     the first unticked task.
  3. Implements the tasks in order. It follows the plan and writes tests tagged
     with the case IDs from tests.md (such as M7-50). It ticks each [ ] → [x] in
     tasks.md as soon as that task and its tests pass.
  4. Verifies. It runs npm test, npm run build and npm run lint, and checks each
     "Done when" item against real output.
  5. Marks the module complete only if everything passes. It ticks the "Done
     when" boxes and reports files changed, test results, any ambiguities it
     resolved, and the next module. Anything that fails or is left over stays
     unticked, with the reason given.
